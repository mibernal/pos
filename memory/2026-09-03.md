# 2026-09-03: Corrección de incompatibilidad text = uuid en worker y desacoplamiento de efectos secundarios

## Contexto del Incidente
El worker del monorepo (`apps/worker`) estaba arrojando repetidamente el siguiente error al procesar eventos `SALE_CREATED` en la cola de salida (`outbox`):
`error: operator does not exist: text = uuid`
en `outbox-sale-created.processor.ts:244` dentro de `executeAsTenantClient`.

El error se presentaba en todas las ventas procesadas después del descargo exitoso de inventario (`sale_inventory_discharged`). Al fallar el paso 1b de efectos secundarios con `throw sideEffectsError`, BullMQ marcaba el job como fallido (`worker_job_failed`) y entraba en un bucle periódico de reintentos, impidiendo que el job ejecutara el Paso 2 (Emisión DIAN). Como consecuencia, las facturas fiscales no se emitían.

## Causa Raíz
1. **Tipado de la base de datos vs Query Raw:**
   La tabla `audit_logs` (migraciones `004_audit_logs.ts` y `027_indexes_and_partitions.ts`) define `entity_id` como `TEXT NOT NULL` para soportar identificadores polimórficos de cualquier entidad del sistema.
2. **Casting inválido en SQL:**
   En `outbox-sale-created.processor.ts:244`, la consulta de verificación usaba:
   `SELECT id FROM audit_logs WHERE entity_id = $1::uuid AND action = 'SALE_CREATED' LIMIT 1`
   y en la inserción subsecuente pasaba `$4::uuid` como valor para `entity_id`.
   PostgreSQL no cuenta con un operador de igualdad implícito para `text = uuid`, por lo que abortaba la consulta de inmediato con `operator does not exist: text = uuid`.
3. **Bloqueo del flujo crítico:**
   La excepción se re-lanzaba (`throw sideEffectsError`), violando la regla de resiliencia del proyecto (MEMORY.md L54): los efectos secundarios no esenciales no deben tumbar la operación principal.

## Solución Aplicada
1. **`apps/worker/src/jobs/outbox-sale-created.processor.ts`:**
   - Se actualizó la consulta `SELECT` sobre `audit_logs` para filtrar por `tenant_id = $1::uuid`, `entity_type = 'SALE'`, `entity_id = $2` (sin cast `::uuid`) y `action = 'SALE_CREATED'`. Esto elimina el error de tipos y aprovecha el índice `idx_audit_logs_tenant_entity (tenant_id, entity_type, entity_id)`.
   - Se actualizó el `INSERT` para pasar `$4` (el `saleId` como string) directamente al campo `entity_id TEXT`.
   - Se eliminó el `throw sideEffectsError` en el bloque `catch`: los fallos en efectos secundarios se registran detalladamente mediante `logWorkerError`, pero no abortan el flujo ni impiden la emisión DIAN.
2. **`apps/worker/test/outbox-sale-created.processor.test.ts`:**
   - Se ampliaron las pruebas unitarias para validar que cuando el evento incluye `audit_payload`, la consulta e inserción a `audit_logs` no utilicen cast `::uuid` sobre `entity_id`.
   - Se añadió un test unitario que simula un fallo en la persistencia de efectos secundarios y comprueba que el job se resuelva sin lanzar errores y ejecute exitosamente la emisión DIAN (`provider.emitSale`).
3. **Documentación:**
   - Se añadió la lección aprendida en `MEMORY.md` bajo "Lecciones Aprendidas & Gotchas".
   - Se registró la decisión arquitectónica `D-063` en `docs/DECISIONS.md`.
   - Se actualizó la tabla de resolución de problemas en `docs/RUNBOOK.md`.
